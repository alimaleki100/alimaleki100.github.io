Snapp Order Center Data Backbone

Managing the data workstream that enabled Snapp users to see orders from multiple ventures in one place, from data pipelines and services to quality monitoring.

Role
Data Product Manager
Company

Timeframe

01 / Product Context

One Order History Across Snapp Ventures

Order Center was designed as a Snapp SuperApp feature where users could see orders from different ventures—including cab, box, shop, market and doctor—in one place.

The data workstream was responsible for the backbone behind that experience. Application feature development was owned by a separate team, so success depended on clear contracts and close coordination between data and application product managers and team leads.

02 / Data Delivery

Pipelines, Data Services and Quality Monitoring

As Data Product Manager, I led a five-person Data Engineering team and coordinated delivery with the application organization using Scrum:

  • Data foundation: Delivered Kafka pipelines and a ClickHouse analytical store for cross-venture order data.
  • Application enablement: Provided APIs and data services consumed by the Order Center application team.
  • Quality and observability: Established data-quality monitoring and operational visibility with Grafana.
  • Dependency management: Worked through delays where individual ventures were not ready to provide the required source data.

Data Backbone

Snapp Ventures Order data supplied by participating services across the SuperApp.
Kafka → ClickHouse Streaming pipelines and analytical storage designed for high-volume data.
APIs & Monitoring Data services for the application team, supported by quality checks and Grafana.
